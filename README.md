# Huzaflix backend

The backend for [Huzaflix](https://github.com/Jolieigena/Huzaflix-Huzapilot), generated by
[HuzaPilot](https://github.com/Huzalabs/huzapilot). It is meant to be edited and committed like any other
code.

| Service | Language | Database |
|---|---|---|
| api-gateway (the single entry point, port 8080) | NestJS | none |
| identity (accounts, login, sessions, password reset) | Python | its own SQLite store |
| projects (project, template) | NestJS | Postgres |
| builds (build, deployment) | Go | Postgres |
| workspaces (workspace, member) | FastAPI | Postgres |

It also includes a generated admin portal (`client-portal`, served on port 5173), a sample-data seeder and
smoke tests (`smoke-test.sh`).

## Run it

You need Docker with Compose.

```bash
./create-env.sh      # makes .env with fresh random secrets (never commit .env)
bash build.sh        # builds and starts everything, then seeds sample data
```

If `./create-env.sh` says "permission denied", run `bash create-env.sh`. The first build is slow because it
downloads and builds every image.

- Gateway: http://localhost:8080 (health check: `/health`, interactive API docs: `/api/docs`)
- Sign in as `admin`. The password is `AUTH_PASSWORD` in `.env`.
- Stop it with `docker compose down`. `docker compose down -v` also deletes all data.

## Settings (`.env`)

`.env.example` lists every setting. The ones you will most likely change:

| Setting | What it does |
|---|---|
| `BROWSER_ORIGINS` | Addresses the frontend may sign in from. Add your deployed frontend address. |
| `AUTH_COOKIE_SECURE` | Set to `true` when the gateway is served over HTTPS. |
| `PASSWORD_RESET` | `off`, `admin` or `email` (see below). |
| `PASSWORD_RESET_URL` | The frontend page that opens from a reset link, for example `https://your-site/reset-password`. |
| `SMTP_*` | Mail server settings for `PASSWORD_RESET=email`. For Gmail, use an app password. |

After editing `.env`, apply it with `docker compose up -d` (or `docker compose up -d identity` for reset and
mail settings).

## Password reset

- `admin`: an administrator creates a one-time link for an account (`POST /auth/accounts/{id}/reset`) and sends
  it to the person. The Huzaflix dashboard has an Accounts page for this.
- `email`: people ask for the link themselves (`POST /auth/forgot-password`) and receive it by email. Accounts
  need an email address.
- Links work once and then expire: 24 hours for admin-issued links, 1 hour for email links.

Secrets such as `SMTP_PASSWORD` belong only in `.env` on the server, never in git.

## Put it on a server

1. Clone this repo on a machine with Docker, then run `./create-env.sh`.
2. In `.env`, set `BROWSER_ORIGINS` to the frontend's address, `AUTH_COOKIE_SECURE=true`, and
   `PASSWORD_RESET_URL`.
3. `bash build.sh`.
4. The gateway listens on `127.0.0.1:8080`, so it is not reachable from outside by itself. Put a web proxy
   with HTTPS (nginx, Caddy or similar) in front of it, with a domain such as `api.example.com`.
5. In the frontend repo's `vercel.json`, forward `/auth`, `/api` and `/health` to that address.

## Regenerate or change it

To add or change services, regenerate with HuzaPilot (the password reset support is on the
`feature/password-reset` branch until it is merged):

```bash
bash huza-multi-generate-project.sh ../Huzaflix-Huzapilot-Backend huzaflix nestjs \
  'projects:nestjs:project,template:postgres:1' \
  'builds:go:build,deployment:postgres:1' \
  'workspaces:fastapi:workspace,member:postgres:1' \
  --lite --password-reset=admin
```

Generating into an existing folder overwrites generated files, so commit your own edits first and review the
diff afterwards.

## Troubleshooting

**`all predefined address pools have been fully subnetted`** when starting. The Docker host has run out of its
default network addresses, which happens on servers that run many Compose projects. Give this project its own
small network with a `docker-compose.override.yml` next to `docker-compose.yml`, using a free range (check with
`docker network ls` and `ip route` first):

```yaml
networks:
  default:
    ipam:
      config:
        - subnet: 10.254.87.160/27   # replace with a free range on your host
```

Keep this file on the server; it depends on that host, so do not commit it.

**`set: pipefail: invalid option name`** when running `build.sh` on Linux. The scripts have Windows line
endings (CRLF), usually because the files were copied from a Windows checkout. Clone the repo on the server, or
export it with `git -c core.autocrlf=false archive HEAD`, so the scripts keep Unix line endings.
